오류검출
( Hamming ) 코드는 전송 데이터에 여러 개의 검사 비트를 
추가하여 오류를 검출하고 수정까지 가능한 방법이다.
이 코드는 재전송 없이 수신 측에서 자체 수정하는 
(② FEC) 방식에 속한다. 
이에 반해 오류 발생 시 송신 측에 재전송을 
요구하는 방식은 (③ BEC)이라 하며, 
여기에 포함되는 대표적 검출 기법으로 (④ Parity) 검사와 
(⑤ CRC) 검사가 있다.
(④ Parity) 검사는 데이터 블록 끝에 1비트 검사 비트를 추가하여 오류를 검출한다.
(⑤ CRC) 검사는 송신측과 수신측이 동일한 특정 다항식을 사용하여 오류를 검출한다.

1.오류를 스스로 고치는 방식
(Forward Error Correction, 전진오류수정)
송신측이 재전송을 할필요없이 수신측이 알아서 오류를 찾아내고 자체적으로 고친다

해밍코드(Hamming Code) => 데이터에 여러개의 검사비트를 끼워 넣어서 보냄
수신측에서 이비트들을 계산하면
오류가 발생했는지 알수 있을 뿐만 아니라
몇 번째 비트에서 오류가 났는지 
그위치까지 정화기 찾아내서 스스로 수정

2.오류를 찾고 다시 달라고 하는 방식(Backward Error Correction, 후진 오류 수정)
수신측에서 데이터를 검사해서 오류가 있는지 없는지 확인 오류가 발생하면
송신측에 ㄷ이터가 깨졌으니 다시 보내줘라고 재전송
우리가 흔희 쓴 ㄴ인터넷(TCP/IP)통신이 대부분 이방식 사용된다

패리티검사 
- 가장 간단한 오류 검출 방식입니다. 
전송하려는 데이터 블록 맨 끝에 
딱 1비트(패리티 비트)를 덧붙입니다.

CRC(Cyclic Redundancy Check,순환중복검사)
현재 네트워크(LAN, 이더넷 등)에서 가장 많이 
그리고 가장 신뢰성있게 쓰이는방식
송신측과 수신측이 미리 수하적인 특정다항식 약속
송신측은 이 당항식으로 데이터를 나는 나머지값을 뒤에 붙이고
수신측도 또같은 다항식으로 나누어 봅니다
나머지가 0으로 딱 덜어지면 정상
아니면 오류로 판단

( OTP )
한번 사용하면 즉시 폐기되어 재사용이 불가하다
서버와 토큰(또는 앱)은 시간 동기화나 카운터 기반 방식으로
메반 새로운 값을 생성하고
내부 검증은 해시 함수를 이용하 방법으로
서버에 평문을 저장하지 않고도 유효성을 확인할수 있다
이 특성 때문에 은행 인증 등 고보안 영역에서 널리 사용되며
재전송 공격방지와 사용자 편의성을 동시에 만족합니다

(OAuth)
사용자가 새로운 사이트에 가입하지 않고 
평소에 이용하던 서비스의 계정으로 로그인할 수 있게 해주는 기술이다.
- 사용자에 비밀번호는 절대 전달되지 않고 사용자가 승인한 범위에 대해서만
접근권한이 위임됨..
- 이방식은 직접인증을 수행하지 않고, "인가(Authorization)" 절차를 
통해 접근 권한을 제3자에게 부여한다.
인증 완료 후, 서비스 제공자는 Access Token을 발급하며 애플리케이션은 
이 토큰을 이용해 API를 호출하여 필요한 정보에 접근한다.
대표적인 소셜로그인 SSO(Single Sign-On)과 달리 동일시스템 내 인증이 아니라
서른 다른 서비스간의 권한 위임에 초점이 맞춰져 있다
